# Кабинет автора и TikTok Direct Post

Страница `/demo/tiktok/authors` открывается без пароля. Владельца TikTok подтверждает Login Kit. До подключения браузер получает случайный идентификатор серверной сессии. Профиль, разрешения и статус отправки доступны только в этой сессии. Для второго автора используйте другой профиль браузера. Рабочие каналы Poster, игровые публикации через OpusClip и их расписания существуют отдельно.

## Настройка стенда

В существующем приложении TikTok включите Login Kit для Web, Display API и Content Posting API с Direct Post. Укажите HTTPS redirect URI с путём `/demo/tiktok/callback`. Для Sandbox добавьте target users. Кабинет запрашивает `user.info.basic`, `video.list`, `video.publish` и `video.upload` (отдельное действие для черновика). У каждого автора своё согласие.

Кабинет обслуживает основной Poster. В его приватном Laravel `.env` включите модуль и задайте параметры ниже. Адрес обратного вызова формируется из `APP_URL` и пути `/demo/tiktok/callback`. Для проверки длительности ролика нужен ffprobe.

```dotenv
TIKTOK_DEMO_ENABLED=true
TIKTOK_DEMO_MODE=sandbox
TIKTOK_DEMO_SANDBOX_KEY=
TIKTOK_DEMO_SANDBOX_SECRET=
TIKTOK_DEMO_UPLOAD=false
```

Production использует существующие TIKTOK_CLIENT_ID и TIKTOK_CLIENT_SECRET приложения. Зарегистрируйте callback кабинета в соответствующей конфигурации TikTok. После одобрения приложения, права и аудита Direct Post переключите **только `TIKTOK_DEMO_MODE=production`**. При использовании Laravel config cache обновите его. Кабинет сбрасывает подключение предыдущего окружения и запрашивает новый вход TikTok. В sandbox разрешена только предложенная TikTok видимость «Только я». В production список определяется текущими настройками автора. Переключатель публикации черновика `TIKTOK_DEMO_UPLOAD` управляет исключительно отправкой фиксированного sample.mp4 во входящие.

## Демонстрация для аудита

1. Покажите будущий продукт, вход и выбор аккаунта TikTok. Скройте адресную строку с кодом OAuth и исключите ввод учётных данных из записи.
2. Владелец выбирает свой короткий MP4 до 960 КиБ, проверяет предпросмотр, имя получателя и подпись. Покажите выбор видимости без значения по умолчанию, разрешения на взаимодействие, маркировку ИИ и коммерческого контента. Параметры аккаунта и лимит длительности проверяются повторно при отправке.
3. Покажите явное согласие и кнопку публикации. Только при отдельном согласовании владелец может отправить свой ролик с видимостью «Только я». До ответа `PUBLISH_COMPLETE` экран показывает обработку или неопределённый результат. Нажмите «Обновить статус» для повторного запроса. При неизвестном исходе проверьте аккаунт перед новой попыткой.
4. Для второго автора повторите вход в другом браузере. Отдельно отметьте, что подтверждено TikTok и какие шаги демонстрировались без отправки.

Direct Post для публичных роликов требует аудита. В заявке указывайте реальную аудиторию, происхождение контента и фактическую готовность продукта. Инструмент только для каналов собственной команды TikTok относит к неподходящим сценариям. [Требования к использованию и UX](https://developers.tiktok.com/doc/content-sharing-guidelines) · [Direct Post](https://developers.tiktok.com/doc/content-posting-api-get-started).

## Проверка и удаление

`php artisan test --compact tests/Feature/TiktokDemo` проверяет сценарий с фиктивными ответами TikTok. Для выключения закройте модуль флагом `TIKTOK_DEMO_ENABLED=false`. После завершения демо можно отозвать разрешения тестовых авторов и удалить Sandbox-ключи. Миграций у демо нет.
